# 奔跑吧，鲸鱼娘 · 摄像头体感躲避跑酷（Cam-Dodge）

基于开源项目 [Jamesun921/cam-run](https://github.com/Jamesun921/cam-run)（190+ star，MediaPipe Pose + Three.js）的**二次创作**。
保留原项目的姿态识别内核，把「无限跑步」玩法替换为「三道躲避 + 计分闯关」。

**当前版本特性**：4 张主题地图（樱花·二次元浪漫 / 地狱·熔岩 / 赛博霓虹 / 星海）、
樱粉二次元浪漫整站界面（开始 / 标定 / 结算 / 暂停 / HUD 全套重做，
详见 `tools/preview-ui.mjs` 出图）、识别与渲染解耦的低延迟操作、
按帧率自动降质的防卡顿机制、键盘与触屏完整兜底。

> UI 性能红线：界面层**禁用 backdrop-filter** —— 无头/软件渲染实测全屏模糊会把
> 帧率拖到 3fps（连标定超时兜底都被饿死）。玻璃质感用「高不透明度深底 + 渐变」实现，
> 不要为了质感把逐帧模糊加回来。

> 项目位置：`D:\cam-run-dodge`（启动方式见下，无需改动任何路径配置）

## 一、快速运行

### 方式 A：双击启动（Windows）

```
双击 start.bat
```

自动起本地服务并打开 `http://localhost:8080`。

### 方式 B：命令行

```bash
node server.js 8080      # 或 python3 -m http.server 8080
```

然后浏览器打开 http://localhost:8080

> **为什么不能直接双击 index.html？**
> MediaPipe 需要 fetch 加载 `.wasm` 与 `.task` 模型，`file://` 协议会被浏览器同源策略拦截；
> 摄像头权限也要求页面处于安全上下文（localhost 满足）。所以必须走本地 http 服务。

### 入口说明

| 文件 | 说明 |
|---|---|
| `index.html` | **主入口，本地离线版**。依赖全部在 `vendor/`，断网可跑 |
| `index-cdn.html` | 备份入口，依赖走 CDN。体积小，但断网白屏 |

## 二、玩法

三条道，角色自动前进，速度随时间递增（普通 13 → 25，困难 18 → 34）。

| 障碍 | 颜色 | 正确操作 | 体感输入 |
|---|---|---|---|
| 低栏 | 🟢 绿 | 跳过去 | 原地起跳 / 高抬腿 / **双手举过肩** |
| 高杆 | 🟠 橙 | 蹲下钻过 | 下蹲 / 屈膝 |
| 实墙 | 🔴 红 | 换道绕开 | 身体左右移动 |
| 小恶魔 | 👹 红身黄眼 | **迎面挥拳打倒**（跳得高也能跃过） | 朝摄像头快速出拳 |

- 每躲过一个障碍 +100 分，连击每级 +10%（上限 3 倍）
- **小恶魔有血条**：普通 3 拳 / 困难 4 拳。每打中一拳就 +70 分并续连击，
  血条清空才倒下（+260 分）。被它撞到只扣 1 条命，而且会拿到一段更长的无敌时间
  （普通 3 秒 / 困难 2.2 秒），恶魔本身也会被撞散 —— **不会被同一只怪连着打掉几条命**。
- **每打中一拳都会把怪击退**（普通 5.5 米 / 困难 5 米，越残血推得越远）。
  这不是花哨特效，而是"还没打死就撞上"的正面解法：怪以每秒十几米迎面撞过来，
  **击退等于把它的逼近进度往回倒一段 —— 命中本身给玩家买回输出时间**。
  光放宽判定阈值是治不了的，那只是让这一拳更容易过判定，并不会让人多出时间。
- **出拳时角色会从手里打出一发光弹**，飞向怪、命中处爆开 ——
  命中是出拳当帧结算的（保跟手），光弹负责把"我打中了"画出来。
  弹是**追踪弹**：每帧瞄向目标怪的实时位置、追上就停在怪身上 ——
  怪在弹飞行的零点几秒里还在逼近，固定落点会让弹从怪身上穿过去（"子弹停不下来"就是这么来的）。
  击退后的怪位置仍是弹的出发点叙事（"子弹把它推走"）；挥空也有一发
  （更小更冷色，飞向空处消散），一眼分得清"这拳中了"和"这拳空了"。
- **什么时候该出拳，游戏分两档告诉你**：
  怪还有约 0.45 秒进窗口时，HUD 先亮「来了！」（浅蓝、弱提示）；
  真进了打击窗口，怪脚下亮起脉动的黄色圆环、HUD 换成「挥拳！」。
  分成两档是有原因的：从"看见提示"到"动作被识别出来"实机有 0.4~0.5 秒延迟，
  只有一档的话玩家看到「挥拳！」再动身，手被识别到时怪已经贴脸了。
  （圆环与提示读的是规则层同一个 `hittable` 标记 —— 判定和画面永远不会各说各话。）

### 等级系统（按距离成长，升级回血，**不设上限**）

跑得越远等级越高，**每升一级血量上限 +1**，还会当场把血补满：

| 项 | 普通 | 困难 |
|---|---|---|
| 每级距离 | 400 m | 450 m |
| 等级上限 | **无** | **无** |
| 血量上限封顶 | **无** | **无** |

开局 5 条命（困难 3 条），跑满 30 级就是 35 条命 —— 这是"跑得久 = 更耐打"的正反馈。

- **血量显示：每 9 点血折成 1 颗金色心**，余数还是红心。
  跑十分钟就攒到三四十点血，一颗颗画红心既排不下、也读不出"自己长进了多少"；
  金心是长期成长的刻度，红心是零头。金心超过 6 颗时 HUD 自动改用「当前/上限」计数。
  正好凝出一颗新金心时，升级提示会单独报一句。
  心形是**内联 SVG + 鎏金渐变**，不是字符 ♥ —— Windows 上字符心会被 emoji
  彩色字形接管，任何 CSS 颜色都改不动它（金心会永远显示成 emoji 的红，踩过）。
  各血量状态的对照图在 `preview/09-血量刻度-金心对照.png`。
- 等级数字在 HUD 左上角；升级会弹提示，一局内连升多级逐级补算，不会漏。
- 重开局 / 换难度，等级与血量上限一起回到起点。
- 注意区分两个"等级"：HUD 上的 `等级` 是**玩家等级**（按距离涨、无上限、涨血量）；
  代码里的 `diffLevel` 是**难度档位**（按距离涨速度/缩短间距，**会封顶**）—— 两者互不影响。
  所以后期血量会越来越厚，但难度不再增长 —— 这是刻意留出来的"成长奖励"区。

### 难度模式（开始屏选择，记在 localStorage）

| 模式 | 命 | 速度 | 障碍间距 | 恶魔 | 设计目标 |
|---|---|---|---|---|---|
| **普通**（默认） | 5 | 13 → 25 | 34 → 24 单位（≈1.0–1.3 秒一波） | 3 拳 | **保证普通玩家能连续运动 10 分钟以上** |
| 困难 | 3 | 18 → 34 | 33 → 18 单位（最快 0.5 秒一波） | 4 拳 | 高速高压，给想被虐的人 |

普通模式之所以敢承诺"10 分钟"，关键不在开局温柔，而在**难度会收敛**：
距离等级每 800 米一档、封顶 6 档，约 200 秒后难度就不再增长。
如果等级无限增长，无论开局多宽松，十分钟后都必然变成地狱。
（`tools/test-game.mjs` 里有一个完美 AI 跑满 600 秒的用例在守着这条约束。）

## 三、技术要点（答辩可讲）

### 1. 识别全部在本地完成

MediaPipe Pose Landmarker 跑在浏览器 WASM/GPU 上，视频帧**不出本机**，
无需上传服务器、无需穿戴设备、零安装成本。这是相比 Kinect / 穿戴方案的核心差异。

### 2. 归一化判定，抗距离变化

直接用像素坐标判定会因为"离摄像头远近"而失效。本项目用**肩宽**做尺度：

```js
dy = (当前髋部Y - 慢基线髋部Y) / 肩宽    // 慢基线会缓慢追随你的漂移，所以 dy 只反映"相对近期姿态"的变化
```

无论站远站近，阈值含义一致；而相对慢基线算，连"慢慢站歪"都会被吸收掉。

### 3. 开局标定（中位数，抗离群）

丢掉前 8 帧热身（人还在调整站姿），再采 32 帧**取中位数**得到个人基准线
（髋部高度、中心位置、身体尺度）。之后所有判定都是"相对本人的位移"，
不同身高 / 体型无需调参。

用中位数而不是平均数，是因为标定期间哪怕只伸手扶一下桌子，
平均值都会被拉偏 —— 基准一偏，你静止站着时系统就认为你一直在"偏离"，于是持续误判。

### 4. 双基线：怎么同时做到"不误触"和"够跟手"

这是体感交互最核心的一个矛盾，答辩时值得单独讲。

问题的根源在于：**人体骸信号里的干扰不是随机噪声，而是低频漂移**（呼吸、重心转移、
衣服轮廓变化），平滑（EMA）对随机噪声有效，对低频漂移几乎无效。
所以"磨平没用" —— 实测人体静止时的漂移量约 ±0.08，
而如果把阈值抬到 0.08 以上又会明显迟钝。

做法是维护**两条平滑轨迹**：

```
慢基线 slow   追踪近期的缓慢漂移，只在判定为"静止"时才以 DRIFT_FOLLOW 追随
快基线 sm     立刻响应真实动作
        → 判定用 dy = sm - slow
```

一旦你的位移越过静止区，慢基线**立刻冻结**；只有你停下来它才慢慢跟上来。
于是"慢慢站歪了、累了换个重心"会被完全吸收掉，
而一次真正的跳跃会在几十毫秒内让快基线远远甩开慢基线 —— 照样跟手。

这套机制调过两轮，两个坑都值得讲：

**坑一：静止判定不能只看"位移幅度"。**
一开始用"最近 400ms 的峰谷差"（STILL_RANGE 0.09）判断有没有在动。
但强漂移下峰谷差本身就被顶到 0.09 以上 → 被判成"在动" → 慢基线永久冻结 →
漂移直接暴露成 dy → 幽灵动作复发。
现在改成**两条判据取或**：峰谷差小 **或** 慢通道速度小（STILL_VEL 0.35/s）。
漂移是慢的、动作是快的，两者差一个数量级，用速度能把大振幅慢漂移稳稳捞回来。

**坑二：一个 EMA 不可能既管"触发"又管"基线"。**
把 EMA 调大换速度，噪声就会涌进基线维护 → 幽灵动作；
把 EMA 压住保稳，动作又慢半拍。这是个死结。
现在拆成两条通道：`EMA`（快，只喂触发判定）与 `EMA_BASE`（慢，只喂静止判定与基线漂移）。
噪声只影响快通道，而快通道的判定全部带"方向 + 幅度"双重门槛，于是提速不再牺牲抗噪。

再配多重护栏：
- **死区**（±0.05 一律归零）吃掉残余抖动
- **攻击时间门**（MAX_ATTACK 420ms）：从离开原位到越过阈值若超过此值，判为"姿势改变"而非跳 —— 慢慢直腰不会触发
- **可见度门**（肩部低于 0.35 的帧直接作废）排除模型"猜"出来的点
- **快通道两级放行**：冲得极猛（> `RISE_VEL_FAST` / `SINK_VEL_FAST`）单通道立刻认账；
  中速则要求快慢两条通道**同时同向**达标（`RISE_VEL` + `RISE_VEL_B`）。
  这样门槛可以压得很低，速度红利拿满、噪声尖峰又混不进来
- **下蹲靠屈膝角**：全身模式下以髋-膝-踝夹角为主判定（噪声不会弯膝盖），
  位置通道只在"快速下沉"或"持续下沉多帧"时才放行
- **变道走短窗口速度**：横向速度（最近 160ms 位移）超过 `LANE_FAST` 且该方向位移已过 `LANE_MIN`，
  就立刻变道，不必等位置慢慢积累到 `LANE_TH`；两个条件同时要求，
  所以"噪声尖峰"（速度快但没净位移）和"慢漂移"（位移够但速度慢）都进不来

有测试量化这个效果：`tools/test-pose.mjs` 里内置了对照，
让"固定基线（退化成旧式实现）"在 100 秒静止输入下产生 **20+ 次幽灵跳跃**，
换成当前的"慢基线"方案为 **0 次**；
`tools/latency.mjs` 则用"3/6/10/15 帧斜坡发力"量化响应速度，
当前最快一档（3 帧发力）起跳 **33ms**、变道/下蹲 **67ms**。

### 5. 判定与画面共用同一个位置（消灭"假撞"）

玩家的横向位置是一个**连续值 `laneF`**（0..2，中间可插值），
**渲染层和碰撞层读的是同一个数**：

```
js/game.js   维护 laneF，用它做碰撞判定
js/scene.js  直接用它画小人的 x，自己不再插值
```

旧做法是渲染层自己插值、判定层用瞬时切换的离散车道，
结果刚按下变道、画面上人才挪出一点点，系统在逻辑上却已经当成"人在左道了"，
于是撞上左道的墙 —— 玩家看到的却是"我根本没碰到"。

### 6. 双模型自动升级 + 现场自诊断（针对"识别不出人体"）

- **快速起步**：默认 lite 模型（5.5MB），推理快；
- **自动升级**：标定阶段连续 25 次检测都找不到人，自动切换到 full 模型（9MB）再试一轮，
  并把偏好写进 localStorage —— 下次直接用高精度起步，不用再等一次切换；
- **暗光自动提亮**：实时测画面平均亮度，偏暗时先做 canvas 提亮再送模型；
- **看门狗**：`requestVideoFrameCallback` 注册了却不回调时（部分摄像头 / 虚拟摄像头会这样），
  1.5 秒内自动改用 rAF 轮询，不让玩家对着黑屏干等；
- **标定屏诊断**：实时显示画面分辨率 / 模型档位 / 检测帧率与命中率 / 亮度，
  并按情况给出"摄像头被占用""光线太暗""离得太近"等具体建议；
- **跳过标定**：只要画面里出现过人就能一键开跑，演示现场不会被卡住。
### 7. 全身 / 半身自适应

讲台空间小、镜头只能拍到上半身时，自动从髋部判定降级为**肩部 + 手腕**判定：
- 全身：髋部上下位移 + 屈膝角度
- 半身：肩部位移 + 双手举过肩

### 8. 分层解耦：识别层与规则层完全分离

```
js/pose.js   姿态识别 → 输出语义信号 { lane, jump, duck }
js/game.js   游戏规则 ← 只接收语义信号
```

**这是二创空间大的根本原因**：想换成"收集金币""打怪闯关"，
只改 `game.js` 的规则，`pose.js` 一行不用动。

### 9. 性能优化

- 障碍物**对象池**（预分配 24 个，运行时不 new）
- 跑道**分段循环复用**（6 段首尾相接，不做无限增长）
- 关闭阴影、像素比上限 2
- GPU delegate 失败自动降级 CPU
- **景物走"精致但限量"**：每侧 16 件（低画质 10 件），且树冠花团这类"堆细节"的零件
  全部用 `InstancedMesh` 合批 —— 樱花一棵树 33 朵花团若是普通 Mesh 就是 528 次 draw call，
  合批后整场只剩 **1 次**。实测（`?keydrive=1` 探针的 `drawCalls`）：
  樱花 ≈ 48 · 地狱 ≈ 54（含修罗魔相 6 尊；两侧普通道具已按需下架，`SCENERY_ON` 一个开关控制），
  都在 1400 的预算线内。**"做得更细"不能以帧率为代价 —— 答辩现场掉帧比物件朴素致命得多。**

### 10. 低延迟：从相机出帧到角色动作，一共几个环节

延迟不是靠某一个参数解决的，链路上有四处会拖时间，缺一处都快不起来：

**(1) 驱动方式** —— 旧版把检测挂在 `requestAnimationFrame` 上，白白多等 1~2 帧：
相机 30fps 而屏幕 60fps，一半渲染帧拿到的是旧数据。
现在改成 **相机出帧即识别**（`video.requestVideoFrameCallback`），
识别完**立刻**把动作喂给游戏逻辑，不等渲染帧。省 16~33ms。
（遇到不回调的摄像头有看门狗兜底，1.5s 无进展自动切 rAF。）

**(2) 绝不隔帧识别** —— 低画质档曾把识别改成"隔帧跑"，那等于把动作延迟直接翻倍。
现在 `setThrottle(1)` 恒定：低端机器上宁可降画质（像素比 / 粒子 / 骨骼重绘），
也要保住体感的响应速度。

**(3) 判定侧**（`js/pose.js`）—— 见上一节：双通道平滑 + 短窗口速度 + 两级快通道。
关键是**不再依赖"对已平滑信号再求导"**：那种双重 EMA 天然滞后两拍，
真起跳的第一帧给不出方向。改成直接看"最近 160ms 里挪了多少"，
真动作一帧就攒够方向与幅度。

**(4) 表现侧**（`js/game.js` / `js/scene.js`）——
识别再快，角色动画慢吞吞挪过去照样钝。变道插值的时间常数从 71ms 降到 36ms
（`laneLerp` 14 → 28），摄像机跟随从 167ms 提到 111ms（跟随系数 6 → 9）。
起跳与下蹲在渲染层本来就是即时切换的，不需要改。

实测（`node tools/latency.mjs`，单位为"从开始发力到首次触发"）：

| 动作 | 3 帧发力 | 6 帧发力 | 10 帧发力 | 15 帧发力 |
|---|---|---|---|---|
| 起跳 | 33ms | 67ms | 100ms | 167ms |
| 变道 | 67ms | 67ms | 100ms | 133ms |
| 下蹲 | 67ms | 67ms | 133ms | 167ms |

慢发力那几档不会更快了 —— 那是物理下限：人还没移动到阈值，任何算法都不该提前认账。

**还有一个容易被忽略的坑：模型档位。**
高精度（full）模型识别更稳，但单次推理约为快速（lite）的 2 倍
（本机无头环境下实测 197ms vs 93ms）。
而"识别不出人体"的自动升级会把 full **永久写进 localStorage** ——
哪怕只是开局光线差了一下，之后每次都被锁在慢模型上，玩家只会觉得"这游戏怎么这么钝"。
现在加了**响应速度看护**：跑起来后若发现"人识别得到、但单次推理 > 45ms"，
自动退回 lite 并更新偏好。人识别不到时不退 —— 那正是需要 full 的场合。

### 11. 性能自适应：任何机器都不卡顿

- 渲染循环恒定 rAF **只负责画**，永远不识别 → 画面流畅
- 识别循环独立驱动，互不阻塞；识别耗时单独计入 HUD
- 自适应降质器每 2.5 秒评估一次 FPS 与单次识别耗时，掉帧时依次降级：
  **像素比 → 粒子/景物数量 → 骨骼隔帧重绘 → 识别隔帧 → 相机降分辨率**，
  恢复后再逐级升回
- 障碍物对象池、跑道/景物/粒子全部循环复用，`update()` 内零对象分配（避免 GC 抖动）

HUD 右上角的 `识别 xx ms` 就是单次姿态识别耗时，绿色 <15ms、黄色 <30ms。

## 五、回归测试

```bash
node tools/test-game.mjs      # 规则层：判定、公平性、视觉一致性、等级、击退、拳弹追踪 （107 项）

node tools/key-e2e.mjs        # 真浏览器：按键链路 / 挥拳反馈 / 连打击杀 / 换景
node tools/preview-shots.mjs  # 出图体检：8 张主题/模型截图 + 1 张血量刻度对照 → preview/
```

前两个不需要浏览器；`key-e2e.mjs` 会自己拉起本地服务和**无头 Chrome**（需要本机装了 Chrome 或 Edge），
真实按下 M / B / 空格 / F 并逐步比对状态，用来守"静态检查证明不了"的那类问题。

**`test-game.mjs`** —— `js/game.js` 的规则层：

- 三类障碍 × 正确/错误操作，共 8 项判定断言
- **挥拳宽容度**：两道之间能打到邻道、窗口最远端能打到、刚越身后还够得着、`hittable` 标记正确
- **击退**（9 项）：命中把怪推远、位置同步到渲染用的 mesh、**不许把怪推出打击窗口**、
  越残血推得越远、击退方向正确不会回头触发撞击；还有一条量化用例 ——
  "从窗口远端开始连打，玩家实际只往前推进了多少"（这就是"打不完 → 打得完"的度量）
- **等级系统**：开局 Lv.1、跨门槛升级、升级回血、一帧跨近 180 级逐级补算、
  **等级与血量都不封顶**（旧实现封顶 30 级 / 9 点血）、换难度重置
- **血量显示换算**（`heartMarkup`，6 项）：9 颗红心熔成 1 颗金心、余数红心、空位、
  金心过多时退回计数 —— 这是 UI 层唯一的纯函数，所以单独拉出来测
- 内置一个"完美操作 AI"跑满 600 秒（一路到最高难度），统计是否出现**无法躲避的死局**，
  并抽检 8 组不同地图布局 × 240 秒全零受击（地图是随机生成的，所以用**播种随机数**
  让每次跑的地图完全一致，否则断言会随机飘红 —— 这是之前踩过的坑）
- **视觉一致性**：验证判定用的位置与画面上的位置是同一个值
  （人还没挪过去就判撞，是"看着没碰到却提示撞到"的根源）
- **资源回收**：重开局、切地图、`clearDemons()` 之后不能有残留在场的网格

改了 `game.js` 的难度参数或生成逻辑后务必跑一遍。

**`test-pose.mjs`** —— `js/pose.js` 的手势识别层。
用合成的关键点序列模拟摄像头输入（噪声幅度可控、结果可复现）：

- 带着白噪声和低频漂移静止站 100 秒 → 要求**零次**误跳 / 误蹲 / 误变道
- 真的做动作时必须在很短延迟内触发（起跳 <400ms、变道 <530ms），
  确保修掉误触发的同时没有牺牲跟手性
- **挥拳三通道各有对应用例**：直拳（前伸+速度）、快速刺拳（只靠极快前伸速度）、
  侧勾拳（手腕画面横扫、z 几乎不变）、小幅出拳（只伸 0.25 个肩宽）、
  以及"手腕缓慢晃动不触发出拳"的反向用例
- **连打节奏**：300ms 一个来回（伸-收-伸）连打 4 秒，要求一拳都不被冷却吞掉 ——
  旧参数（COOLDOWN 320 / REARM 380）在这条用例上会掉拳，那正是"打不完就被撞"的成因之一
- 内置一组对照：让"固定基线（退化成旧式实现）"跑同样的 100 秒静止输入，
  会复现出大量幽灵动作（当前约 20 次误跳），换成当前的"慢基线"方案为 0 次，可直接对比

现场如果换了摄像头或光线环境，跑一遍就能确认参数是否还合适。

## 六、调参指南

### 手感（js/pose.js 顶部的 `CONFIG` 对象）

全部参数集中在这一处，改完刷新页面即可生效。

| 参数 | 默认 | 说明 |
|---|---|---|
| `EMA` | 0.5 | 快平滑系数（只用于 `sm` 快基线）。**越大越跟手**，抖得厉害就调小（如 0.4） |
| `DEAD` | 0.06 | 竖直死区：\|dy\| 在此之内一律归零，吃掉残余抖动 |
| `RISE` | 0.15 | 起跳阈值（相对慢基线）。**低于 0.10 就开始出现"没跳却自己跳"** |
| `RE_ARM` | 0.08 | 滞回：dy 回到此范围内才允许下一次起跳，防止连续误跳 |
| `MAX_ATTACK` | 420 | 攻击时间(ms)：从离开原位到越过阈值若超过此值，判为"姿势改变"而非跳 |
| `PRED` / `RISE_VEL` / `RISE_VEL_FAST` | 0.05 / 1.1 / 1.8 | 起跳速度预判：正以足够速度上冲时提前放行，省 1~2 帧 |
| `DROP` | 0.15 | 下蹲阈值（位置通道）；需配合屈膝角 / 持续多帧才放行 |
| `STILL_RANGE` | 0.09 | 静止判定的峰谷差：最近窗口内位移小于此值才算"站住没动" |
| `STILL_WIN` | 400 | 静止判定窗口(ms) |
| `DRIFT_FOLLOW` | 0.05 | 慢基线追随速度（静止时）。调大=更易跟着你慢慢站歪，误触发也会变多 |
| `REBASE_RATE` | 0.12 | 持续保持的新姿势（站起/坐下）重锚基线的收敛速度 |
| `REBASE_DELAY_UP` / `DOWN` | 500 / 1600 | 上述重锚的延迟(ms)；坐下更保守，以免吸收主动长蹲 |
| `LANE_TH` | 0.30 | 变道阈值（相对横向参考）。调小更灵敏但会误变道 |
| `LANE_STRONG` | 0.62 | 越过此值（如识别丢帧后甩很远）不等确认立刻变道 |
| `LANE_STEP` | 0.20 | 最近窗口内横向挪动量超过此值才算"迈了一步" |
| `LANE_BACK` | 0.18 | 回中滞环，防止在边界反复横跳 |
| `LANE_DWELL` | 90 | 变道后最小驻留时间(ms)；左右乱跳就加大 |
| `X_FOLLOW` | 0.03 | 人站中间区域时横向参考的缓慢跟随速度 |
| `JUMP_COOLDOWN` | 280 | 一次起跳的最小间隔(ms) |
| `DUCK_RELEASE` | 80 | 蹲姿释放延迟(ms) |
| `MIN_VIS` | 0.35 | 肩部关键点可见度门槛，低于此值整帧当作不可靠、直接作废 |

**往哪边调，取决于你要什么：**

- 还是想更跟手 → `EMA` 调到 0.7，`RISE` 最低到 0.10，`LANE_STRONG` 调到 0.5。
  **不要**再往下压 `RISE`，那已经进入人体自然漂移的区间了。
- 现场光线差 / 摄像头很糊、仍然偶尔误动 → `MIN_VIS` 提到 0.5，
  `DEAD` 提到 0.08，`DRIFT_FOLLOW` 降到 0.04，`STILL_RANGE` 提到 0.11。代价是动作要做得更标准一点。

改完建议跑 `node tools/test-pose.mjs` 确认两端都还站得住（不误触 + 跟得上）。

**"没做动作却乱动 / 太灵敏"先查这里**：除了上面的动作阈值，
`_createLandmarker` 里的三个模型置信度（`minPoseDetectionConfidence` 等，当前 0.45）
决定"画面里什么东西会被当成人体"。早先压到 0.4 是为了保住半身入镜的极端场景，
但代价是杂物、椅背、人影都会输出一组飘忽的关键点 —— 玩家自己没动、游戏在乱动。
现场觉得太灵敏，先把它提到 0.5（官方默认），半身入镜出问题再降回来。

### 挥拳识别（js/pose.js 的 `CONFIG.PUNCH_*`）

挥拳比跳/蹲/变道难：MediaPipe 的 **z 轴噪声大、动态范围小，而且每个摄像头都不一样**，
只靠"拳头前伸多少"这一个通道判定，实机上十有八九打不出来。
所以这里走**三通道融合**，任一条成立即出拳：

| 通道 | 条件 | 覆盖的动作 |
|---|---|---|
| ① 直拳 | 前伸量 `ext > PUNCH_EXT` **且** 前伸速度 `> PUNCH_VEL` | 正常出拳 |
| ② 快速刺拳 | 前伸速度 `> PUNCH_VEL_FAST` **且** `ext > PUNCH_EXT_MIN` | 又快又浅的刺拳 |
| ③ 侧勾拳 | 手腕画面移动速度 `> PUNCH_SPD2D` **且** 手在躯干高度以上 | 侧勾/斜拳（z 几乎不变，前两条都抓不到） |

| 参数 | 默认 | 说明 |
|---|---|---|
| `PUNCH_EXT` | 0.24 | 前伸量阈值（肩宽比例）。**调小 = 更容易打出**；原值 0.42 在实机上几乎够不着 |
| `PUNCH_VEL` | 1.35 | 前伸速度阈值（肩宽/秒）。**低于 1.0 会被 z 轴噪声伪造出假出拳**（噪声 ±0.008 × 归一化后约 0.95/s），别再往下压 |
| `PUNCH_VEL_FAST` | 2.2 | 极快前伸的单速度通道阈值 |
| `PUNCH_EXT_MIN` | 0.09 | 走速度类通道时的最小前伸量，防手臂乱晃 |
| `PUNCH_SPD2D` | 3.0 | 手腕画面移动速度阈值（肩宽/秒），侧勾拳通道。**觉得"随手一抬就出拳"就调大它** |
| `PUNCH_BACK` | 0.12 | 收回到此以内才算"收拳"，允许下一次出拳 |
| `PUNCH_REARM_MS` | 240 | 出拳后强制解除 latch 的时间(ms)，防止"忘记收拳"把连打卡死 |
| `PUNCH_COOLDOWN` | 190 | 两拳最小间隔(ms)。**这三条一起决定"能打多快"** —— 见下面的连打节奏 |

**连打节奏（为什么是 190 / 240）**：怪贴脸时打击窗口只开一秒多，而打光一条血要好几拳。
旧的 320 / 380 意味着最快也只有 3 拳/秒，再叠上人的反应与识别延迟就是打不完 ——
所以这三个数一起放宽，让"一伸一收就能接着打"由玩家的手来决定。
下限卡在 190ms，是因为一次真实的收拳至少要这么久，再短会把一拳算成两拳。

**打不出来时怎么查**：按 `P` 打开调试面板，出拳瞬间看 `punchSrc` ——
它形如 `Rz` / `Lv` / `Rw`，字母是手（L/R），后缀就是命中的通道（`z` 直拳 / `v` 刺拳 / `w` 侧勾）。
一直是空的说明三条通道都没过：先看 `extL` / `extR`（前伸量）够不够，
再对着上表降阈值；`PUNCH_VEL` 是唯一不要往低压的那个。

### 等级与打击手感（js/game.js 的 `MODES` / `CFG`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `levelUpDist` | 400 / 450 | 每多少米升一级（普通 / 困难）。等级与血量都**不设上限** |
| `punchWindow` | 36 / 44 | 挥拳有效距离：恶魔在 `-punchWindow ~ +punchReach` 之间才够得着。**调大 = 更早能出拳** |
| `punchReach` | 3.8 / 4.0 | 已越过身后的宽容距离（刚擦身而过还能补一拳，用来补识别延迟） |
| `knockback` | 5.5 / 5 | **每命中一拳把怪沿来路推远多少米**（残血时按比例再加，最多 ×2）。绝不许把怪推出 `punchWindow` 之外 —— 那样玩家会以为后面几拳全空了 |
| `CFG.punchLead` | 0.45 | 「来了！」预警的提前量（秒）。按当前速度折算成距离，**不**算进真正的打击窗口 |
| `CFG.punchLaneTol` | 0.62 | 挥拳的车道容差。**比撞墙的 `laneTol`(0.45) 宽** —— 拳头有长度，够得着邻道边缘；这也是"站在两道之间也能打到怪"的原因 |

### 判定宽容度与手感（js/game.js 的 CFG）

| 参数 | 默认 | 说明 |
|---|---|---|
| `laneTol` | 0.45 | 碰撞的车道容差。**调小 = 更容易躲过**；调大会开始出现"看着没碰到却判撞" |
| `laneLerp` | 12 | 变道插值速度。走完一条道约 250~300ms（≈真人侧步节奏）；调大变道更快更硬朗，但会跟玩家身体动作的节奏脱节（28 的"瞬移感"实测过又降回来了） |

### 难度（js/game.js 的 CFG）

`speedStart` / `speedMax` / `speedRamp` / `lives` / `invincible` / `jumpV` / `gravity`。

### 新增地图（js/scene.js 的 THEMES）

复制一份现有主题改配色即可，字段含义见文件内注释。
必备字段：`name / swatch / anime / sky / fog / ground / laneLine / rail /
player / obstacle(hurdle|overhead|block) / scenery / particle / lights`。
`anime: true` 会启用卡通材质（MeshToonMaterial），适合二次元风格。
改完跑 `node tools/verify-wiring.mjs` 校验字段齐全。

## 七、常见问题

**Q：提示"摄像头不可用"？**
Chrome/Edge 需页面为 https 或 localhost。检查是否被其他软件（会议/直播）占用摄像头。

**Q：没有做动作，角色却自己跳 / 自己变道？**

这是动态阈值问题，不是摄像头故障。人站着不动时 MediaPipe 的关键点本来就在抖，
加上呼吸、重心转移的缓慢漂移，换算到判定量上大约有 ±0.08 的波动幅度。
如果起跳阈值设得比这个小，就等于把噪声当成了操作。

现在默认参数（`RISE` 0.13）已经站在两者的安全间隔里。
若现场环境很差：先看按 `P` 打开的调试面板 —— 站着别动，观察 `dy` 和 `dxRaw` 的波动范围，
把 `DEAD` 设到略大于这个范围，`RISE` / `DROP` 设到这个范围的 2 倍以上，
`LANE_TH` 同理对照 `dxRaw`。改完跑 `node tools/test-pose.mjs` 验证。

**Q：画面上明明没碰到障碍物，却提示撞到了？**

这类问题统一归结为"判定用的位置和画出来的位置不是同一个"。
现在两者都读 `laneF`（玩家的连续横向位置），渲染层不再自己插值，
所以理论上不会再错位。如果还有，检查这两处：

- `game.js` 的 `CFG.laneTol`（默认 0.45）：数值越大判定越宽。**想更容易躲过就调小。**
- 重开局或按 `M` 换过地图后画面里出现"卡住不动的墙" —— 那是资源回收没生效，
  已被修复，回归测试里有一条专门守着这个问题。

另外 `P` 面板里的 `lane` 值应与你在画面上看到的位置一致，不一致就说明还是有错位。

**Q：挥拳打不到小恶魔？**

先看**恶魔脚下有没有亮黄圈 / HUD 有没有弹「挥拳！」** —— 亮了才是打击窗口，这时出拳才有效；
没亮说明还没到距离（或它不在你这条道上）。

注意 HUD 提示是**两档**的：浅蓝的「来了！」表示怪还有约 0.45 秒进窗口 ——
**看到它就该动身了**，别等「挥拳！」。因为从你看见提示到动作被识别出来，实机有 0.4~0.5 秒延迟，
等强提示再挥，手被识别到时怪已经贴脸了。

如果提示亮着、你也在挥拳，但面板里的 `punchSrc` 一直是空的，就是挥拳没被识别到。
按 `P` 打开调试面板对着上文「挥拳识别」那一节调参：三条通道（直拳 / 刺拳 / 侧勾拳）
总有一条适合你的动作习惯，实在不行用键盘 `F` 兜底演示。

**Q：反应慢半拍，还没打死小恶魔就被撞上了？**

这一版专门治过这个问题，而且是从玩法上治的（不是靠调阈值）：

- **每打中一拳都把怪击退**（普通 5.5 米，越残血推得越远）—— 命中本身给自己买回输出时间；
- 出拳间隔从 320ms 收到 **190ms**、打击窗口从 26 米扩到 **36 米**（困难 30 → 44）；
- 提示加了一档**提前 0.45 秒的「来了！」**，把识别延迟垫掉。

如果你仍然觉得来不及，按这个顺序动参数（`js/pose.js` 与 `js/game.js`）：

1. `PUNCH_COOLDOWN` / `PUNCH_REARM_MS` 再往下调 —— 但别低于约 150ms，否则一次挥拳会被算成两拳；
2. `knockback` 调大（普通 5.5 → 7）—— 每拳都能多买一点时间；
3. `punchWindow` 调大（36 → 44）—— 更早就能开打，但要靠「来了！」提示让玩家看得懂。

反过来，如果**故意想让恶魔更难缠**：把 `knockback` 压到 2~3、`punchWindow` 收回到 30 即可。
改完跑 `node tools/test-game.mjs` —— 里面有一组"击退"断言守着（含"不许把怪推出窗口"这条）。

**Q：点了「摄像头体感模式」却直接变成了键盘游戏？**
标定阶段 12 秒内一直没识别到人体就会自动降级（画面有提示），
现在不会再默默把你踢出去 —— 标定屏会实时显示诊断信息并给出具体建议：

| 诊断项 | 含义 | 建议 |
|---|---|---|
| 画面 | 摄像头实际分辨率 | 显示「未取到画面」通常是被腾讯会议/微信/OBS 占用了 |
| 模型 | 快速(lite) / 高精度(full) | 连续 25 次检测不到人会自动升级到 full，并被记住 |
| 检测 | 检测帧率 · 命中率 | 命中率长期 0% 说明画面里确实没有可被识别的人体 |
| 亮度 | 画面平均亮度 | 低于阈值会自动提亮处理；低于 45 建议直接开灯 |

常见处理：站正对镜头、上半身完整入镜、距摄像头 1.5–2.5 米、别逆光。
只露上半身也能玩（自动切半身模式，用肩膀 + 手腕判定）。
标定卡住时可按标定屏上的「跳过标定，直接开跑」，或按 ESC 回首页重试。
**Q：识别到了但角色不动？**
按 `P` 打开调试面板看 `dy` / `dxRaw` 数值。站着不动时应接近 0；
做动作时 `dy` 应有明显变化（跳为负、蹲为正，`|dy|` 通常能到 0.4 以上）。
若变化很小，说明动作幅度不够或人离摄像头太远。

**Q：操作不够跟手 / 有延迟感？**
按 `P` 打开调试面板看 `识别ms`（单次识别耗时）和 `识别帧率`。
- `识别ms` > 30：机器算力不够，自适应降质会自动介入；也可手动把相机分辨率调低
- `识别ms` 很低但仍觉得迟钝：调 `CONFIG.EMA` 到 0.7、`RISE` 到 0.13（别再低了）
- 举手比原地跳更容易被识别（半身模式下尤其明显）

**Q：帧率低于 30 / 画面卡顿？**
自适应降质器会自动降级（HUD 会提示"性能自适应：低画质"）。
仍卡的话：换 Chrome（MediaPipe 在 Chrome 上最优）；关掉调试面板（按 `P`）；
按 `M` 换到粒子较少的地图（赛博霓虹粒子最少）。

**Q：想换成"收集金币"玩法？**
只改 `js/game.js`：把 `_spawn` 里的障碍物改成金币、把 `_collide` 改成"碰到即得分"，
`pose.js` 完全不用动。
